### 1.2 与 GDD 的三处偏差（都是有意为之）

|---|---|---|---|

## 2. 品质分级

`scripts/data/crop_quality.gd`（`class_name CropQuality`）

| 等级 | 名称 | 售价倍率 | 背包 item id |
|---|---|---|---|
| 0 | 普通 | ×1.00 | `turnip` |
| 1 | 银星 | ×1.50 | `turnip_silver` |
| 2 | 金星 | ×2.00 | `turnip_gold` |

**为什么把品质编码进 item id，而不是给背包加第二个维度？**
`GameState.inventory` 是 `Dictionary[StringName]int`。要做 `{id, quality}` 复合键，背包 / 出货箱 / HUD 三处都得改；编码进 id 只需要一个 `CropQuality.split()`，而且天然支持「金星番茄 ×3」这种堆叠。
代价是**任何拿到 item id 的地方都必须先 split**，为此专门留了两条测试：`milk` 和 `milk_large` 都不许被误判成金星（`_gold` 后缀碰撞检查）。

## 3. 肥料系统

`scripts/data/fertilizer.gd`（`class_name Fertilizer`）

| 等级 | 名称 | 价格 | 银星加成 | 金星加成 | 生长 |
|---|---|---|---|---|---|
| 0 | 未施肥 | — | 5%（底子） | 0% | — |
| 1 | 基础肥 | 100G | +5 / +10 / +15% | 0% | 不变 |
| 2 | 高级肥 | 300G | +12 / +20 / +28% | +3 / +5 / +8% | **+1 天**，需求「高」的作物 +0 天 |

（加成三档分别对应作物的**施肥需求 低 / 中 / 高**；「中」档就是 GDD 写的 +10% / +25% 基准。）

于是施肥变成一个有取舍的动作，而不是无脑操作：

- **草莓 / 花椰菜 / 甜瓜 / 南瓜 / 蓝莓**（需求高）→ 高级肥最划算：加成最高，还免掉 +1 天。
- **芜菁 / 小麦 / 大蒜 / 冬葱**（需求低）→ 上高级肥等于白搭一天，只该上基础肥。
- **土豆 / 番茄 / 玉米 / 山药**（需求中）→ 时间紧就基础肥，钱多就高级肥换品质。

**规则细节**
- 肥料只能施在**已耕地**上（`NOT_TILLED`）；不能降级（基础肥盖不掉高级肥，返回 `ALREADY_BETTER`），可以升级。
- **一次性作物收获后肥料归零**（被这一茬吃掉了），**再生作物保留**（同一株还在长）。
- 土壤底边会画一条肥力色带：基础肥棕 / 高级肥绿，玩家不用点开面板就知道哪格施过肥。
- 开局补给 30 袋基础肥 + 10 袋高级肥；**肥料商店 / 堆肥属于经济模块**（下一模块），所以本模块不消耗金币。

## 4. 季节限制

```gdscript
# FarmGrid
var season: int = -1          # -1 = 不限制（测试 / 沙盒）
func plant_reason(cell, crop_id) -> StringName
# → OK / NOT_TILLED / OCCUPIED / UNKNOWN_CROP / WRONG_SEASON / OUT_OF_BOUNDS
```

- `main._ready()` 与 `EventBus.season_changed` 都会把 `GameClock.season` 同步进 `_grid.season`，**门禁永远跟着时钟走**。
- 播种失败不是静默返回 `false`，而是回一个**原因码**：`main` 拿它给玩家说人话（「南瓜 是秋季作物，现在春季种不活（Tab 换种子）」），测试拿它做精确断言。这是本模块最值钱的一个重构——把「能不能种」和「为什么不能种」分开。
- 换季时**地里没成熟的老作物不会死**（比 Stardew 宽容），但只能种新季节的作物。
- `season = -1` 是给测试和沙盒留的后门，老测试 `FarmGrid.new()` 不设 season，所以里程碑 2 的 44 项断言原样通过。

## 5. 与时间系统联动

`GameClock`（autoload）→ 每 tick 推进游戏分钟 → `_roll_day()` → `EventBus.day_advanced` → `main._on_day()`：

```
main._on_day()
├─ _grid.advance_day()      # 作物：浇过水 → days_grown+1；没浇 → dry_days+1
│                           # 2 天枯萎 / 4 天枯死；成熟当天广播 {"type":"mature"}
├─ _herd.advance_day()      # 动物（里程碑 3）
├─ _apply_weather_day()     # 雨天自动浇满 / 暴风雨灾害（模块 2）
└─ 汇总成一条玩家提示："成熟可收 3 株 | 作物枯萎 1·枯死 0 | 雨天自动浇水 12 格"
```

`advance_day()` 的**全局语义**必须记住：调一次 = 全世界过一天。测试里如果只给一格浇水，其余格子会一起变渴，写测试时必须把同批格子一起喂水（这个坑在模块 3 的测试里踩过一次，已写成注释）。

成熟天数 = `crop.grow_days + Fertilizer.growth_delta(亲和度, 肥料等级)`，所以 `is_mature()` / `growth_ratio()` / `days_left()` 全都用**实际天数**算，不会出现「施肥后进度条卡在 100% 但不熟」。

## 9. 踩过的坑

1. **`_draw()` 里的肥力标记会被作物盖住。** 一开始把三颗小点画在格子中央偏下，正好落在幼苗/灌木的底边上，截图放大后什么都看不见。改成**格子底边一条 3px 色带**（`o.y+29..31`）——本格作物最低只到 `base = o.y+28`，下一格作物从 `o.y+41` 才起步，这条带子永远露着。
2. **`advance_day()` 是全局的。** 测试里想「只让 A 格长大」，结果同批格子一起渴死了；`for i in range(4): g.water(a); g.advance_day()` 这种写法必须把所有相关格子一起喂水。
3. **`advance_day()` 新增 `mature` 事件后，`main._on_day` 的 `else: died += 1` 会把「成熟」统计成「枯死」。** 原来是 `if wither / else dead` 的二分，加第三种事件必须换成 `match`。
4. **肥料在截图里看不见，不是没画，是被盖住**——同一个坑的两种表现（见 1）。
5. **品质倍率照 GDD 走（1.5 / 2.0），不要自己发明 1.25 / 1.5。** 第一版按「常见游戏手感」写了 1.25/1.5，和 GDD §3.3 §4.1 对不上，全部返工。
6. **概率表断言不能用 `Array ==`。** `0.05 + 0.10 = 0.15000000000000002`，`== [0.15, 0.0]` 必挂。测试里加了 `_chance_is()` 用 `absf(差) < 0.0001` 比。
7. **向日葵的 GDD 原值是亏本数据**（种子 200 / 售价 80 / 一次性）。这类「表里就写错」的数值只能靠一条「全表回本断言」兜住——写测试时顺手就把数据 bug 抓出来了。
8. **`milk_large` 差点被 `_gold` 后缀匹配误伤。** 品质 split 是从后往前匹配后缀，畜产品 id 里恰好有 `_large`。已加断言锁死。
9. **`UI` 的第一个子节点必须是 WeatherVFX**（模块 2 的断言），所以新增 `ToolBar` 只能**追加到末尾**。
