> 目标：把「种出来 / 养出来」的东西变成「钱」，再把钱变成「更大的产能」。
> 五条需求：背包（堆叠/拖拽/使用）· 商店（种子/动物/工具/饲料 买卖）· 订单（限时委托）·
> 加工品（牛奶→奶酪等）· 售价随品质/季节波动。
>
> 测试：**1400 项断言 / 12 套全绿**（本模块新增 **247** 项）
> 提交：见 `git log`

## 0. 一图看懂：钱怎么转起来

```
              ┌──────────────┐
  种子/肥料 ──▶│   种植系统    │──▶ 作物（带品质后缀）
              └──────────────┘            │
              ┌──────────────┐            │
  饲料/药剂 ──▶│   动物系统    │──▶ 奶/蛋/毛（带品质）│
              └──────────────┘            │
                                          ▼
              ┌────────────────────────────────────┐
              │  加工坊 Processor（2 槽，24h 开工）  │
              │  牛奶×2 → 奶酪 · 羊毛×2 → 毛线      │
              │  品质继承原料（金星奶 → 金星奶酪）   │
              └────────────────────────────────────┘
                                          │
                     ┌────────────────────┼────────────────────┐
                     ▼                    ▼                    ▼
              ┌────────────┐      ┌────────────┐      ┌────────────┐
              │  出货箱     │      │  订单板     │      │ 杂货铺回收  │
              │ 一键全卖    │      │ ×1.5 报酬   │      │ 单件零售    │
              └────────────┘      └────────────┘      └────────────┘
                     └────────────────────┼────────────────────┘
                                          ▼
                                    Market.price()
                          基础价 × 品质 × 季节 × 当日行情
                                          │
                                          ▼
                                       💰 金币
```

**唯一定价入口是 `Market.price(item, season, day)`。**
出货箱、订单报酬、杂货铺回收、背包详情、加工品增值判断，全部走它。
模块 3 时代出货箱自己乘 `CropQuality × SeasonEffects`，模块 7 之后那样的第二处乘法就是 bug 温床。

## 2. 数据层：ItemDef / ItemDB / RecipeDB

### 2.1 为什么物品要有一个 Resource

模块 6 结束时，物品被拆在**四个地方**：

| 来源 | 内容 | 认领方式 |
|---|---|---|
| `CropDB` | 24 种作物 | `crop_of_item(id)` |
| `CropDB.seed_item` | 24 种种子（`seed_<crop>`） | `crop_of_seed_item(id)` |
| `ProductDB` | 畜产 / 消耗 / 材料 | `has(id)` / `kind_of(id)` |
| `Fertilizer` | 2 档肥料 | `level_of_item(id)` |

想做一个「列出背包里所有东西」的界面，就得写四路 `if`；想加一类新物品（加工品），
就要动这四路里的每一路。所以模块 7 引入一层**聚合**：

```
ItemDef (Resource)
  id / display_name / category / base_price / stack_max
  sellable / buyable / color / note
```

`ItemDB` 在启动时把上面四张表 + `upgrades.csv` 全部转成 `ItemDef` 塞进 `items` 字典。
**数值不复制**：`base_price` 是运行时从各自 DB 读的快照，改 CSV 之后 `rebuild()` 就同步。

### 2.2 品质不进 ItemDef

品质仍然编码在 **item id 后缀**里（模块 3 定的规矩：`milk` / `milk_silver` / `milk_gold`）。

```gdscript
ItemDB.resolve(&"milk_gold") == ItemDB.resolve(&"milk")   # 同一个 ItemDef
ItemDB.quality_of(&"milk_gold") == 2                        # 品质单独拆
ItemDB.price_of(&"milk_gold") == 200                        # 基础 × 2.0
```

好处：背包结构零改动、`CropQuality` 的倍率表全项目复用一次。
代价：任何拿到 item id 的地方都必须先 `split()` —— 这条坑在模块 3 就记过了，模块 7 又踩了一次（见 §7 坑 3）。

### 2.3 可卖 / 不可卖

| 类别 | `sellable` | 理由 |
|---|---|---|
| CROP / PRODUCT / CRAFTED | ✅ | 经济循环的三条主线 |
| SEED | ❌ | 种子是投入品，误卖会很痛 |
| CONSUMABLE（饲料/药剂/肥料） | ❌ | 顺手全卖 = 灾难 |
| MATERIAL（木材） | ❌ | 建材不是商品（杂货铺卖 60G，但出货箱不收） |
| TOOL（升级券） | ❌ | 不进背包，买了直接生效 |

`ItemDB.is_sellable()` 是出货箱、订单池、回收页的**共同真相**。

## 3. 背包：从「字典计数」到「真槽位」

### 3.1 结构

```gdscript
# 真源
slots: Array = [null, {id: &"turnip", count: 3}, null, ...]   # 长度 = slot_capacity()
# 派生索引（只读缓存）
inventory: Dictionary = {&"turnip": 3}                        # id -> 总数
```

- `slot_capacity()` = `40 + (bag_level - 1) × 8` → **40 / 48 / 56**
- `add_item(id, n) -> int` 返回**实际放进去的数量**（满了不会静默吞掉）
- `remove_item(id, n) -> bool` 从**后往前**扣，前面的格子不会跳
- `move_slot(from, to) -> "moved" / "merged" / "swapped" / "noop"`
- `drop_slot(i, n)` 丢东西
- 每次变更后 `_rebuild_index()` 重建 `inventory`

**为什么保留 `inventory` 字典**：出货箱 / HUD / 商店 / 订单全都按 id 查总数，
把它们改成遍历槽位是一次零收益的重写，而且极容易漏。

### 3.2 拖拽的三条分支

| 落点 | 行为 | 返回值 |
|---|---|---|
| 空格 | 整格移过去 | `moved` |
| 同 id 且未满 | 合并，余量留在原格 | `merged` |
| 同 id 但已满 | 什么都不做 | `noop` |
| 不同 id | 交换两格 | `swapped` |

写在这里而不是 UI 里，是为了能 headless 断言（见测试 §3）。

### 3.3 使用语义在 main，不在 UI

`InventoryUI` 只发 `use_requested(index)`。语义在 `main._on_inv_use()`：

1. **种子** → `_player.set_seed(crop_id)`，关背包（省得 Tab 翻过 24 种）
2. **消耗品**（肥料/饲料/药剂）→ 提示去世界里用（肥料 6/7 号工具，饲料 4 号，药剂空手）
3. **作物 / 畜产 / 加工品** → 提示去出货箱或加工坊

## 4. 经济四件套

### 4.1 Market：四因子定价

```
单价 = 基础价(CSV) × 品质倍率(CropQuality) × 季节倍率(Market) × 当日行情(Market)
```

| 品类 | 春季 | 夏季 | 秋季 | 冬季 | 行情波动 |
|---|---|---|---|---|---|
| 作物 crop | 1.00 | 1.00 | **1.10** | 1.00 | ±15% |
| 畜产 animal | 1.00 | 0.95 | 1.00 | **1.10** | ±15% |
| 加工品 crafted | 1.00 | 1.00 | 1.00 | 1.00 | **±7.5%** |
| 其他 other | 1.00 | 1.00 | 1.00 | 1.00 | ±15% |

**行情因子是确定性的**：`_noise(day, cat)` 用 `hash("%d|%s")` 打散，
同一天同一品类永远同一个数。好处：

- 测试能直接断言「第 7 天牛奶价 = 第 7 天牛奶价」
- 将来做存档，读档不会因为多按了一次而变价
- HUD 显示的 1.03x 和实际结算**是同一个数**（保留三位小数）

**加工品波动减半**是刻意的：加工的价值主张就是「价格稳、不赌行情」。
让它跟原料一样乱跳，加工坊就只是个更麻烦的出货箱。

### 4.2 加工坊：RecipeDB + Processor

`data/recipes.csv`（4 列）：`output,input,count,minutes`

| 加工品 | 原料 | 耗时 | 成本 → 卖价 |
|---|---|---|---|
| 奶酪 cheese | 牛奶×2 | 2h | 200 → 240 |
| 精品奶酪 fine_cheese | 大罐牛奶×1 | 3h | 200 → 480 |
| 山羊奶酪 goat_cheese | 羊奶×2 | 2h | 260 → 310 |
| 毛线 yarn | 羊毛×2 | 3h | 360 → 420 |
| 高级毛线 fine_yarn | 细羊毛×1 | 4h | 360 → 830 |
| 羊驼毛线 alpaca_yarn | 羊驼毛×1 | 4h | 420 → 970 |
| 蛋黄酱 mayonnaise | 鸡蛋×1 | 2h | 50 → 120 |
| 黄金蛋黄酱 gold_mayonnaise | 金蛋×1 | 3h | 150 → 360 |
| 鸭蛋酱 duck_mayo | 鸭蛋×1 | 2h | 80 → 185 |
| 松露油 truffle_oil | 松露×1 | 4h | 300 → 700 |
| 蜂蜜酒 mead | 蜂蜜×2 | 6h | 300 → 380 |

`Processor` 是**纯逻辑**（RefCounted，不碰场景/UI/GameState）：

```
start(recipe, quality) → 占一个槽，remain = minutes
advance_minutes(m)     → 递减，到 0 就 ready，返回「这一帧刚做完的」
take(i)                → {output, count, quality}，槽清空
```

- 槽位：Lv1 = 2 / Lv2 = 4 / Lv3 = 6（`Processor.set_level` 已支持，本模块只开 Lv1）
- **品质在放料那一刻读一次**，中途不可变 → 金星牛奶做的必然是金星奶酪
- 时间单位是**游戏分钟**，`tick_advanced(10)` 推进，和时钟天然对齐

### 4.3 订单板：OrderBoard

| 规则 | 值 | 出处 |
|---|---|---|
| 刷新周期 | 每 3 天 | GDD §5.5 |
| 同时挂单 | 最多 2 单 | 本模块 |
| 期限 | 刷新日 + 2 天，第 2 天 14:00 截止 | GDD §5.5「14:00 前送达」 |
| 报酬 | `行情价 × 数量 × 1.5`，再 ±10% 小费（取整到 5G） | GDD §5.5 |
| 成就 | 完成 10 单 → 「村中名人」 | GDD §5.5 |
| 订单池 | 能卖 + 基础价 ≤ 600G（排除觉醒专属/稀有货） | 本模块 |

时间用**绝对分钟** `day × 1440 + minute` 比较，不用 `(day, minute)` 二元组 ——
跨日那一刻的边界条件少一半。

`OrderBoard` 只返回事件和结算信息，**不碰背包也不碰金币**：

```gdscript
tick(day, minute, pool, season) -> [{type:"new"/"expired", order}]
can_deliver(order, GameState.count_item) -> {ok, need, have, reason}
deliver(order) -> {order, item, count, reward, npc, famous}
```

副作用（扣物品 / 加钱 / 弹提示 / 解锁成就）全在 `main._on_order_deliver()`。

### 4.4 工具铺：upgrades.csv

| id | 工具 | 等级 | 价格 | 材料 | 效果 |
|---|---|---|---|---|---|
| hoe_2 | 锄头 | 2 | 1500G | 木材×5 | 3 格直线 |
| hoe_3 | 锄头 | 3 | 4000G | 木材×12 | 3×3 |
| can_2 | 洒水壶 | 2 | 1500G | 木材×5 | 3 格直线 |
| can_3 | 洒水壶 | 3 | 4000G | 木材×12 | 3×3 |
| bag_2 | 背包 | 2 | 800G | 木材×5 | +8 格（40→48） |
| bag_3 | 背包 | 3 | 2000G | 木材×12 | +8 格（48→56） |

GDD §5.4 写的是「铁×5 / 金×3」，但本项目**没有铁矿和金矿**（也没有矿系统）。
用杂货铺能买到的**木材**替代，价格与效果不变。等将来加了矿再换材料列，只改 CSV。

工具范围由 `main._tool_cells(cell, level)` 算，是纯几何：

```gdscript
Lv1 → [cell]
Lv2 → cell, cell+d, cell+2d      # d = 当前朝向主轴
Lv3 → 以 cell 为中心的 3×3
```

## 5. UI 设计

### 5.1 背包（`I` 键）

```
┌─ 背包 35/40 格 · 35 种物品 ──────────────┐   ← 标题：用量 + 种类
│ ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐              │   8 列 × 5 行（40 格）
│ │▣││ ││ ││ ││ ││ ││ ││ │              │   每格 26×26 + 2px 间隙
│ └─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘              │
│  ...（4 行）                            │   格内：色块 + 品质星 + 数量
│ 芜菁种子 ×3 · 单价 21G · 春季 · 4 天成熟  │   ← 信息条：选中格的详情
│ ←→↑↓ 选格 · E 使用 · X 丢 1 个 · 拖拽…   │   ← 操作提示
└─────────────────────────────────────────┘
```

- **物品图标 = 色块**（`ItemDef.color`）：24 种作物已有 CSV 色，加工品手工挑色，其余用 id 哈希出柔和色
- **品质星**画在格子右上角（银 `#C8D6E5` / 金 `#F2C14E`）
- **中文物品名不画在格子里**：`draw_string` 用默认字体，中文会缺字 —— 放底部信息条用 `Label`
- 键盘和鼠标并存：方向键选格 / E 使用 / X 丢 1 个 / 左键点选 / 右键使用 / 拖拽换位合并

### 5.2 商店壳的五种语义

`ShopUI` 不知道自己卖的是什么，只按 `mode` 发信号：

| 场景 | 信号 | 谁处理 |
|---|---|---|
| 买（种子/动物/杂货/工具） | `buy_requested(id)` | `main._on_buy()` |
| 卖（杂货铺回收页） | `sell_requested(id, all)` | `main._on_sell()` |
| 选父母（繁殖棚） | `buy_requested(uid)` | `main._on_breed_pick()` |
| 交订单 | `buy_requested("order:N")` | `main._on_order_deliver()` |
| 放料（加工坊） | `buy_requested("cheese@2")` | `main._on_craft_start()` |

`main._on_buy()` 开头按 `_shop_kind` 分流，所以「一张货架 = 一行」这个约定被五个系统复用。

`price = 0` 表示「这一行不是买卖」（选动物 / 交订单 / 放料），不显示价格列。

## 7. 踩坑清单（本模块 10 条）

### 1. PowerShell 管道改文件会把 UTF-8 中文打成乱码

`Get-Content | Set-Content` 在 PS 5.1 下默认按 GBK 读写，一次 `-replace` 就把 `main.gd` 的
中文注释和字符串全变成 `�?`，还顺手吞了几个换行。

**规矩：改文件只用 `edit_file` / `write_file`，永远不用 shell 管道。**
这次是靠 `git checkout -- scripts/main.gd` 救回来的（代价：重做 6 处编辑）。

### 2. 品质不拆 → 金星牛奶做不了奶酪

第一版 `_craft_entries()` 按基础 id 列货架（`milk`），但背包里金星牛奶是 `milk_gold`，
`count_item(&"milk")` 查不到它 → 玩家看着背包有奶却做不了。

**修法**：货架按品质分行（`cheese@0` / `cheese@1` / `cheese@2`），entry id 带 `@q`，
`main.parse_craft_entry()` 拆回 `{rid, quality}`。

### 3. `var h := abs(hash(...))` 推断成 Variant，被当成错误

项目开了「警告即错误」。`abs()` 的签名是 Variant，`:=` 会推断成 Variant。

**修法**：用 `absi()`（int 版）。同类还有 `mini`/`maxi`/`clampi`。

### 4. `_ready()` 里只 refresh 不 tick → 开局一张订单都没有

`_refresh_orders()` 只是把状态灌进节点，**不生成订单**。
`_ready` 里必须调 `_tick_orders()`（它会先 `OrderBoard.tick()` 再 refresh）。

### 5. HUD 第 3 行会和右上角时钟打架

`ClockBg` 占 `x = 632-196 .. 628`。HUD 的 `offset_right` 必须从 632 收到 **442**，
否则长文本会钻到时钟底下。模块 4 踩过一次，模块 7 加第 4、5 行时又踩一次。

### 6. ToolBar 塞 3 行会溢出压住 Prompt

`font_size 9` 的实际行高约 13px，3 行 = 39px > 原来的 30px 高。
**修法**：ToolBar 250..296，Prompt 298..316，Tip 318..356。

### 7. `OrderBoard.DUE_MINUTE` 是「相对 6:00」的 480，不是 840

`GameClock.minutes` 是**当日已过分钟**（0 = 6:00）。14:00 对应 480。
写成 `14*60` 会让截止时间跑到第二天 20:00。

### 8. 加工坊 Lv1 只有 2 槽，玩家第一天就会撞上

`_craft_entries()` 在槽满时把每一行都变灰并写「槽满了」，
而不是让玩家点了没反应。`_open_craft_panel()` 在有成品时**直接取货**，不弹面板 ——
收东西不该多点两次。

### 9. 出货箱的 `unit_price` 语义变了，旧测试要跟着改

模块 3 的测试钉死 `unit_price(&"turnip") == 35`。模块 7 之后它含当日行情（±15%）。

**修法**：拆成两个函数 —— `base_price()`（标价，不含行情，测试用它）
和 `unit_price()`（实收，含行情）。旧断言改 3 条，并新增「实收在 ±15% 内」的区间断言。
这是**规格演进**，不是回归。

### 10. `ShopUI` 打开那一帧必须屏蔽输入

玩家按 E 触发 `Interactable` 和面板吃到的是**同一个 InputEvent**。
不屏蔽就会出现「一按 E 开了商店又立刻买了一件」。
模块 4 就修过，模块 7 加 SELL 模式时把这条约束抄进了 `_confirm()` 的调用链。
