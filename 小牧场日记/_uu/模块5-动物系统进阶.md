## 2. 觉醒事件数据结构（需求 ① 的交付物）

`scripts/animal/awakening.gd` —— 纯数据 + 纯查询，**不碰节点、不碰 UI**。
`Awakening.event(species)` 返回的字典就是「觉醒事件」的全部契约：

```gdscript
{
    "species":   StringName,     # 物种 id，与 animals.csv 一致
    "persona":   String,         # 拟人化名字（对话框标题左半）—— "布伦希尔德"
    "title":     String,         # 称号（标题右半）—— "牧场之母"
    "portrait":  Color,          # 立绘色块：UI 画一个纯色方块，零素材
    "lines":     Array[String],  # 拟人化台词，逐句推进（2–3 句）
    "gift":      StringName,     # 觉醒专属产物 id（必须在 products.csv 里）
    "gift_name": String,         # 产物中文名（提示条文案用）
}
```

### 触发链路（一次觉醒，四件事同时发生）

```
好感 → 1000 的**那一瞬间**（喂食 / 抚摸 / 刷毛 / 抱抱 / 留棚 +3，全部走 _gain()）
  ① AnimalState.awakened = true（永久）        + just_awakened = true（一次性标记）
  ② main._check_awakenings() 扫到标记 → EventBus.animal_awakened
  ③ EventBus.dialogue_requested(Awakening.speaker(), lines, portrait) → DialogueUI 弹对话
  ④ 以后每天产出时 30% 概率把当天的产出换成 gift（product_awakened）
```

**觉醒的收益**（一次性给足，不留尾巴）：

| 效果 | 说明 |
|---|---|
| 免疫生病 | 再也不会 `sick`，不需要药剂 |
| 免疫衰减 | 漏喂不 −15、冷落不 −2（它有灵性，自己觅食、自己找乐子） |
| 特殊产出 | 每天 30% 概率产出觉醒专属产物（1 件，不叠品质星） |
| 石碑点亮 | 秘密花园里对应的那座石碑变金顶 + 该物种的颜色宝石 |

> 为什么觉醒要豁免「冷落 −2」：不豁免的话好感会从 1000 掉到 998，
> `hearts()` 是整除 → 显示 9 心，跟「永久觉醒」这个状态自相矛盾。

## 3. 成长阶段（需求 ②）

| 物种 | 成年天数 | 备注 |
|---|---|---|
| 鸡 | **3 天** | 需求指定 |
| 绵羊 | **5 天** | 需求指定（模块 4 是 8 天，本轮改成 5） |
| 奶牛 | **7 天** | 需求指定 |
| 鸭 4 / 火鸡 5 / 猪 6 / 山羊 6 / 羊驼 10 / 蜜蜂 2 | | 沿用模块 4 |

`AnimalState`：

```gdscript
enum Growth { BABY, ADULT }
growth_stage()      # BABY / ADULT
stage_name()        # "幼年" / "成年"
display_label()     # "幼年奶牛" / "奶牛"（HUD 与提示条都用它）
days_to_mature()    # 还有几天成年（成年 = 0）
body_scale()        # 0.62 → 1.0 线性长大，AnimalNode 直接拿它当缩放
```

* **渲染**：`AnimalNode` 不再写死 `0.7`，改读 `body_scale()`。所以幼崽是「一天天长大」的，不是一个开关。
* **门禁**：幼年不产出（`is_producing()` 要求成年）、不能繁殖（`Breeding` → `BABY`）。
* **刷毛例外**：幼崽**可以**刷毛（当抚摸用）。拦住幼年的是「剪毛产出」，不是刷毛本身。
  ⚠️ 别在 `brush()` 里加 `is_adult()` —— 模块 4 的测试就是拿幼崽刷的毛。
* **开局演示**：牧群最后一只（索引 8）是**幼年火鸡**，开局就能看见成长过程。
  ⚠️ 必须加在最后：模块 4 的测试按索引取动物（`animals[5]` = 绵羊、`animals[7]` = 蜜蜂）。
* **跨日事件**：`mature`，只在那一天广播一次。

## 4. 生病系统（需求 ③）

### 触发（沿用模块 4，补了「治疗」这一半）

```
好感 < 3 心  且  连续漏喂 ≥ 2 天   →  每天 15% 掷骰生病
生病期间：不产出 · 每天 −20 好感 · sick_days += 1
```

### 恶化与治疗

| 天数 | 事件 | 玩家看到的 |
|---|---|---|
| 第 5 天 | `critical` | 「病危 N 只 —— 明天不用药就没了」 |
| 第 7 天 | `died` | 「病逝 N 只」，`Herd` 把动物移出牧场、动物层重建 |
| 任意一天用药 | 康复 | `cure()`：`sick = false`、`sick_days = 0`、好感 **+30** |

* **怎么用药**：空手（工具 5）站在生病的动物前按 `E`。空手交互的第一优先级就是「治病」。
* **药剂**：`products.csv` 新增 `medicine / 药剂 / 180G / consumable`，**杂货铺**有卖，开局送 3 瓶。
* **没药**：拒绝治疗并提示「杂货铺买药剂，拖到第 7 天就救不回来了」。
* **康复回补好感 +30**：治病是补救措施，不是惩罚玩家 —— 药已经花了 180G 了。

## 5. 繁殖系统（需求 ④）

### 建筑表 `data/buildings.csv`

```
id,name,price,material,material_count,gestation_days,note
breeding_shed,繁殖棚,1200,wood,20,3,同种成年动物两只 · 各需 8 心以上
```

`BuildingDB`（autoload）读它，所以**改造价 = 改 CSV**，代码一行不动。
加「鸡舍 / 谷仓 / 温室」= 加一行 CSV + 抄一遍 main 的建造流程。

### 规则（`scripts/animal/breeding.gd`，纯逻辑）

| 门槛 | 值 |
|---|---|
| 繁殖棚 | 必须已建成 |
| 两只 | 同种、不同个体、**都成年**、都不生病、都不在妊娠 |
| 好感 | 两只都 ≥ **8 心** |
| 牧场 | 没住满（`Herd.MAX_ANIMALS = 20`） |
| 一次成本 | **100G + 干草饲料 ×5** |
| 妊娠 | **3 天**（来自 buildings.csv） |

`can_breed()` 返回**枚举** `Reason`，不是 bool —— 只回 bool 的话
「没盖棚」和「好感不够」在 UI 上分不开，玩家只能干瞪眼（模块 3 的 `plant_reason()` 已经证明过这点）。

```
OK / NO_SHED / SAME / SPECIES / BABY / HEARTS / SICK / PREGNANT / SPACE
```

### 生崽

```
妊娠倒计时在 AnimalState.advance_day() 里递减
  → 归零广播 {type: "born", species}
  → Herd.advance_day() 收到 born，在**母亲身边 20px** 处 add() 一只
  → 新生个体 days_old = 0（幼年），广播 {type: "birth"}
  → main 看到 birth/died 就把 AnimalLayer **rebuild**（refresh 同步不了「多一只」）
```

### 界面

复用 `ShopUI` 这个通用壳：`_breed_entries()` 把牧群列成货架，
点一只选一只（选中的打 ✔，标题切成「选第二只」），选满两只立刻结算。
成交逻辑（扣钱 / 扣饲料 / 挂妊娠）全在 `main.gd`，**UI 一行没改**（只加了个 `update_title()`）。

## 6. 秘密花园（需求 ⑤）

### 解锁条件

**每个物种至少有一只动物觉醒**（9/9），按**物种**算，不按个体。
理由：牧场有 20 个位置，把每一只都喂到 10 心是纯重复劳动，不是玩法。

```
Herd.all_species_awakened()
  → GameState.set_flag(&"garden_unlocked", true)
  → EventBus.garden_unlocked + 解锁对话
  → GardenGate 的提示从「沉睡」变成「E 进入秘密花园」
  → GardenDecor 从不可见变可见（9 座石碑按觉醒情况点亮）
```

### 新地图的几何（`WorldConfig`）

| 常量 | 值 | 说明 |
|---|---|---|
| `GARDEN_ORIGIN` | (832, 32) | 主地图右侧，中间留 64px 视觉缝 |
| `GARDEN_TILES` | 20 × 12 | = 640×384 px，比视口大，相机 limit 才不会比视口小 |
| `GATE_POS` | (744, 288) | 主地图一侧的藤蔓门 |
| `GARDEN_ENTRY` / `FARM_ENTRY` | (1152, 340) / (704, 288) | 两个落点 |
| `GARDEN_FOUNTAIN` | (1152, 224) | 喷泉，9 座石碑围着它排一圈（半径 116） |

**⚠️ `MAP_PX` / `camera_limits()` 一点没动**（模块 1 的测试把主地图尺寸钉死了）。
花园走自己那套：`garden_camera_limits()` / `camera_limits_for(in_garden)`，
`main._update_zone()` 按玩家坐标切换。

**⚠️ 花园的碰撞是另一个 StaticBody2D**（`World/GardenCollision`），
没塞进 `WorldCollision` —— 那个节点的子节点数被模块 1 的测试钉成了 `fence + bounds = 9`。

### 花园里有什么

* 十字石板路 + 喷泉（`GardenDecor._draw`，纯几何，零素材）
* 一圈花坛（确定性摆放，不随机 —— 截图和测试都要可复现）
* **9 座觉醒石碑**：每个物种一座，觉醒了就金顶 + 该物种颜色的宝石，没觉醒刻一个问号
* 回程传送门（花园四周是实心围墙，这是唯一出口）

> 花园目前是**纪念性**的（+ 一段解锁对话），没有新的生产玩法。
> 这是有意的：模块 5 的交付重点是「全部觉醒 → 有东西给你看」这条正向反馈闭环，
> 不是又开一条经济线。

## 10. 踩的坑（9 条）

1. **命名枚举不能用 `Class.MEMBER` 访问**。
   `enum Reason { OK, ... }` 必须写 `Breeding.Reason.OK`；
   `Breeding.OK` 会报 `Cannot find member "OK" in base "Breeding"`。
   （`FarmGrid.OK` 能用是因为那边根本不是 enum，是一堆 `const StringName`。）
   → 顺手记：`--check-only --script` 查不了 autoload 引用，别拿它当完整检查。
2. **测试里造动物时 uid 撞车，把三种失败原因全吞了**。
   第一版按「物种+心数」拼 uid，于是两只 9 心奶牛 uid 相同，
   `can_breed` 的第一关 `a.uid == b.uid` 直接返回 `SAME` ——
   「未成年 / 生病 / 妊娠」三条断言全挂。→ uid 加自增序号。
3. **`debug_feed_full()` 之后喂不进去**。它把 `fed_today` 直接拉到 `feed_freq`，
   `is_hungry()` 立刻变 false，「喂到 10 心觉醒」的测试第一步就被拒。
   → 想测喂食，用 `fed_today = 0`，别用 `debug_feed_full()`。
4. **「高好感不会病」这条断言的第一版是错的**。
   把好感设成 900 然后 200 天不喂 → 漏喂 −30/天，30 天后就掉到 0 了，
   然后照样生病。→ 改成「罚完仍有 3 心」（每轮把好感钉回 400），
   才真正验的是 `hearts() < 3` 那个门槛。
5. **解锁条件按物种算，开局只有 6 种**。
   开局牧群是 牛×2/鸡×3/绵羊/鸭/蜜蜂/火鸡 = **6 个物种**，
   而解锁要求 9 种 → 测试里必须先 `add` 山羊 / 猪 / 羊驼。
   第一版没加，`garden_unlocked` 死活不亮，藤蔓门提示「觉醒 6/9 种」。
6. **花园的 4 面墙不能塞进 `WorldCollision`**。
   模块 1 的测试断言那个节点的子节点数 == `fence_walls() + bounds_walls() = 9`。
   → 另起一个 `StaticBody2D`（`GardenCollision`），两边各自干净。
7. **`MAP_PX` / `camera_limits()` 一个字节都不能动**。
   模块 1 把 `[0,0,768,448]` 钉死了。花园走 `camera_limits_for(in_garden)`，
   `camera_limits()` 保持原样 —— 老测试零回归。
8. **生崽 / 病逝必须 `AnimalLayer.rebuild()`，不能只 `refresh()`**。
   `refresh()` 只同步已有节点的坐标，多一只少一只它看不见（屏幕上会留一具「幽灵牛」）。
   → `_on_day` 里扫 `birth` / `died` 事件决定 rebuild 还是 refresh。
9. **截图脚本站位被隔壁动物「抢焦点」**。
   站在 (560,268) 想拍奶牛，结果 `_handle_animal` 喂的是 17px 外的蜜蜂（截图里提示写着「喂了蜜蜂」）。
   → 站位统一用 `cow.pos + Vector2(-30, 0)` 面朝右，跟测试里的 `_stand_near()` 一致。
