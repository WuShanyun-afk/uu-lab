## 3. 好感度：0–10 心（需求 ③）

1 心 = 100 好感，封顶 1000。

### 获取

| 行为 | 值 | 限制 |
|---|---|---|
| 喂食 | **+10** / 餐 | 每天 `feed_freq` 次（奶牛 2 次、家禽 1 次） |
| 抚摸 | **+5** / 次 | 每天 `pet_limit` 次（蜜蜂 = 0，摸不到） |
| 刷毛 | **+8** / 天 | 仅 `brushable` 的物种（牛/山羊/绵羊/羊驼） |
| 抱抱 | **+6** / 天 | 仅家禽 |
| 雨雪留棚 | +3 | `WeatherSystem` 给，不在这里 |

### 衰减（每次跨日结算）

| 情况 | 值 |
|---|---|
| 漏喂 | **−15** / 餐 |
| 喂饱但被冷落 | **−2** / 天 |
| 生病 | **−20** / 天 |

**「冷落」的精确定义**：该物种**所有能做的互动一个都没做**。

* 蜜蜂不能摸、不能刷、不是家禽 → 只喂食就够，永远不会被判冷落（否则它每天白掉 2 点）。
* 漏喂当天**不叠加**冷落 —— 同一件事不罚两次。

### 其它

* 好感 < 3 心 且连续漏喂 ≥ 2 天 → 每天 15% 掷骰生病；生病期间不产出、每天再 −20。
* 0–2 心：10% 概率当天不产出。
* ≥ 8 心：触发特殊产出（`high_chance <= 0.0` 表示必定，否则按概率）。
* 品质按心数：≥9 心金星 / ≥6 心银星 / 其余普通。

## 4. 挤奶 / 剪毛节奏条（需求 ④）

### `scripts/data/rhythm_bar.gd` —— 纯逻辑，headless 可断言

一条 0–1 的轨道，指针往返跑，目标区随机落在 0.25–0.75。

```
score = 1 - |pos - 目标区中心| / 半宽     # 中心 1.0，边缘 0.0
```

| 等级 | 条件 | 产出效果 |
|---|---|---|
| 完美 PERFECT | score ≥ 0.80 | 产量 **+1**、品质 **+1 档** |
| 不错 GOOD | score ≥ 0.50 | 品质 **+1 档** |
| 还行 OK | 在目标区内 | 无加成 |
| 失手 MISS | 跑出目标区 / 4 秒超时 | 产量 **−1**（最少 1） |

`RhythmBar.apply_result(grade, count, quality)` 是纯静态函数，所以「打几分 → 给多少」完全可单测。

### `scripts/ui/minigame_ui.gd` —— 只画，不算

* 操作：`E` / 空格 出手 · `Esc` 放弃（放弃**不消耗产出**，可以重来）· 4 秒不按 = 失手。
* 亮区（绿）+ 甜点区（亮绿）+ 指针（进区变白）+ 底部黄色剩余时间条。
* 亮 0.7 秒成绩再收起来，成绩同时写进底部提示条。

## 5. 商店（需求外的加分项）

### `scripts/ui/shop_ui.gd` —— 通用商店壳

只做三件事：显示货架、选、把 `id` 丢出去。成交逻辑全在 `main.gd`。
**加工具店 / 家具店 = 造一份 entries，UI 一行不改。**

货架条目：

```gdscript
{id: StringName, name: String, price: int, note: String,
 enabled: bool, reason: String}
```

操作：`↑↓`/`W S` 选择 · `E`/`Enter` 买下 · `Esc`/`Q` 关掉 · 钱不够的项灰显 + 注明原因。

### 两个可交互物

| 物件 | 位置 | 卖什么 |
|---|---|---|
| `SeedShop` 种子摊 | (416, 176) | **当季 6 种**种子 + 基础肥 + 高级肥 |
| `AnimalShop` 动物牌 | (416, 248) | `AnimalDB` 全表 9 种，按价格升序 |

两者都**只发 `EventBus.shop_requested`**，不碰 UI、不碰金币（零耦合）。

### 种子变成消耗品了

模块 3 里播种不消耗任何东西。模块 4 起：

* 种子是背包物品，id = `seed_<crop_id>`（`CropDB.seed_item()`）。
* 开局每季作物各给 3 颗（共 72 颗），之后靠种子商店补货。
* 播种消耗 1 颗；没有就拒绝并提示去种子商店。
* 出货箱不会误卖种子（`crop_of_item` / `ProductDB` 都不认识 `seed_` 前缀）。

### 动物商店

* 卖的是**成年**动物，买下立刻 `debug_ready_produce()` —— 玩家能马上试挤奶小游戏，不用等 7 天。
* 落点从 `SPAWN_SLOTS`（围栏内 12 个空位）里挑第一个没动物的；牧场满了退钱。

## 8. 踩的坑（10 条）

1. **CSV 列索引忘了跟着表头改**。`animal_db.gd` 里还留着旧 12 列的 `row[3] = price`，于是奶牛价变成 `int("barn") = 0`，整张表静默错位。
   → 教训：CSV 是 schema，改表头必须同步改解析器，并且**必须有断言把数值钉住**。
2. **产物 id 不能以 `_gold` 结尾**。`duck_egg_gold` 会被 `CropQuality.split()` 当成「金星鸭蛋」，`ProductDB.has()` 直接查不到。
   → 改叫 `duck_egg_jumbo` / `turkey_egg_jumbo`，并在测试里钉一条「大鸭蛋不会被误判成金星」。
3. **子节点在父节点 `_draw()` 之后绘制**。节奏条的面板底色原本是 `ColorRect` 子节点，结果把整条轨道盖得干干净净（截图里只有一块黑板）。
   → 底色改在 `_draw()` 里自己画。
4. **打开面板那一帧的 `E` 会被面板再吃一次**。「一按 E 开了商店又立刻买了一件」。
   → 用 `Engine.get_process_frames() == _open_frame` 守卫，商店和节奏条各一份，并有专门断言。
5. **`plant_reason()` 的「调用即种下」副作用会咬人**。种子商店要求「先确认种得下，再检查有没有种子」，但 `plant_reason()` 一调就把作物写进地块了。
   → 加 `dry_run` 参数（默认 `false`，老行为不变，里程碑 2/3 测试零回归）。
6. **HUD 背包行被 24 种种子撑爆**，糊到右上角时钟上。
   → 种子汇总成「种子×72」一项，HUD 开 `autowrap`。
7. **冷落判定必须按物种能力算**。第一版写「没摸没刷就 −2」，蜜蜂直接每天白掉 2 点好感。
   → `AnimalData.can_be_pampered()`：抚摸上限 > 0 或能刷毛或是家禽。
8. **冷落不叠加在漏喂上**，否则「一天没管」会被罚两次（−30 和 −32 的差别就是体感）。
9. **测试里不能直接把玩家丢到 `animal.pos`**。隔壁那只更近会抢焦点（捡蛋测试第一次收成了蜂蜜）。
   → 加 `_stand_near()`：站到目标左侧 30px、面朝右，`interact_point()` 正好落在动物身前 10px。
10. **弹窗期间必须冻玩家**，否则商店开着还能 WASD 乱跑、还能用工具。
    → `EventBus.ui_modal` 一个开关，`Player` 只认它，不知道是谁弹的 UI。
