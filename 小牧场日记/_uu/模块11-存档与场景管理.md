## 2. 存档数据结构（v4）

一份存档 = **18 段 JSON**，一段对应一个系统（模块 8 定下的三层结构，模块 9/10/11 只加段不改结构）：

```
{
  "version": 4,
  "saved_at": 1760000000, "saved_at_text": "2026-10-18 15:10:00",

  "meta":      { day, season, year, clock, weather, gold, animals, awakened, garden,
                 scene, scene_name },          ← 摘要（标题页「继续游戏」只读这一段）
  "scene":     { id, entry, pos: [x, y] },      ← 模块 11 新增：在哪个场景 / 哪个入口 / 坐标

  "clock":     { day, season, year, minutes, phase, paused },
  "weather":   { today, yesterday, rng_state, ... },
  "state":     { gold, slots, tool_levels, barns, stats, story_flags, perks,
                 secret_recipes, flags },        ← GameState（含背包真槽位）
  "farm":      { season, rng_state, tiles },     ← 农田（每格作物/浇水/肥料）
  "herd":      { animals, rng_state, ... },      ← 动物（含好感/成长/怀孕）
  "orders":    { orders, completed, failed, last_refresh_day, rng_state },
  "processor": { level, slots },
  "player":    { x, y, facing, facing8, tool, seed },
  "buildings": { stage, items },                 ← 模块 9：建筑账本 + 牧场阶段
  "npcs":      { masa: {id, points, met, talk_day, gift_day, gifts}, ... },   ← 模块 10
  "story":     { done, acts, counters, endings }                              ← 模块 10
}
```

**槽位**（`SaveSystem`）：

| 槽 | 名字 | 谁写 | 说明 |
|---|---|---|---|
| 0 | 自动存档 | 跨日 2:00 | 面板里**只读**，手动 S 不许覆盖 |
| 1 | 快速存档 | F5 | F9 优先读这个 |
| 2–5 | 存档 1–4 | 存档面板 S | 多存档位，可删可覆盖 |

**原子写**：`写 .tmp → 校验长度 → 旧档挪 .bak → 改名 → 删 .bak`（模块 8 的底座，没有变）。
**迁移**：`migrate(from_version)` 只加不改 —— v1→v2 补 buildings、v2→v3 补 npcs/story、
v3→v4 补 `scene`（老档默认「在牧场」）。

```
                              │ 睡着的机器  │
                              └─────────────┘

  回牧场时：新 main._ready()
     ├─ SceneRouter.register_scene("farm", capture, apply, get_pos, set_pos)
     ├─ var carry = SceneRouter.take_carry()

```

**读档的流程**（`SceneRouter.load_session`）：

```
SaveSystem.load_slot(slot)
  ├─ apply_global_state(d)            GameState / GameClock / WeatherSystem（autoload，任何场景都灌）
  ├─ carry = d                       农场那一局先揣着
  ├─ 读 d.scene.{id, entry, pos}
  └─ target == 当前场景 ?
       ├─ 是 → _apply(d, pos)         原地读档（模块 8 的 F9 秒回，不闪屏）
       └─ 否 → change_scene_to_file(target) → 新场景 _ready 里 take_carry() 接住
```

## 4. 关键设计（为什么这么做）

### 4.1 为什么需要 `carry`，而不是「把所有系统都搬进 autoload」

`change_scene_to_file` 会把 `main` 整个 free 掉，而农田 / 牧群 / 建筑 / 订单 / 加工槽的真源
都在 `main` 的成员变量里。两条路：

- **A（未采用）**：把这些系统全部搬进 autoload —— 等于重写模块 3–10 的每一处引用；
- **B（采用）**：离开牧场那一刻 `capture()` 出一份**完整存档字典**揣在 `SceneRouter.carry` 里，
  回来时 `apply()` 塞回去。房间场景根本不碰农场数据，只读 autoload。

B 的好处：`capture` 直接复用模块 8 的 `_build_save()` —— **换场快照和存档是同一个东西**，
不可能出现「少存一个字段导致读档回牧场丢进度」。

### 4.2 四个回调（场景与路由的契约）

| 回调 | 牧场 | 房间 |
|---|---|---|
| `capture()` | `_build_save()` 全量 | 留空（carry 原样带着） |
| `apply(d, pos)` | `_apply_save(d)` + 落位 | 只落位 + 关 UI |
| `get_pos()` | `_player.global_position` | 同上 |
| `set_pos(p)` | 设坐标 + 相机对齐 | 同上 |

### 4.3 房间为什么只有一个脚本

屋内 / 镇上 / 商店 / 矿洞结构完全一样（地板 + 出口 + 可交互物）。给每间写 80 行脚本，
改一次提示文案要改四遍 —— 所以房间描述进 `RoomData`，场景脚本只有 `RoomScene` 一个。

`RoomScene` 还顺手解决了「房间场景没有 main」的两个问题：
- `DialogueUI` 自己不订阅信号（主场景是 main 转发的）→ 房间自己接一次；
- 商店面板要有人喂货架 → 房间本地写一个 30 行的买/卖（只卖消耗品，不碰 main 的完整交易）。

### 4.4 存档面板为什么是 autoload

面板如果挂在场景里，换场瞬间会跟着 current_scene 一起被 free ——
玩家看到「面板闪一下就没了」。autoload 挂在 root 上，换场不影响。

## 5. 键位

| 键 | 作用 |
|---|---|
| F5 | 快速存档（槽 1） |
| F6 | 存档面板（↑↓ 选槽 · S 存 · L 读 · D 删 · Esc 关） |
| F9 | 读最近的档（快速 → 自动 → 最新手动） |
| E | 对着门 / 出口 / 床 / 存档柜 / 柜台 / 机器交互 |

存档面板在**任何场景**都能开（autoload），走到屋内对着「存档柜」按 E 也能开。

## 6. 踩过的坑

1. **`change_scene_to_file` 是下一帧生效**：改完 `current_id` 之后不能再碰旧场景的节点指针
   （模块 8 踩过 free 后访问）。所以 travel/load 只改状态 + `call_deferred("_change_scene")`。
2. **截图脚本必须挂在 root 上**：把驱动逻辑写在 `current_scene` 上，第一次换场脚本自己就没了。
   `get_tree().root.add_child.call_deferred(driver)` —— 而且在 `_ready` 里直接 `add_child` 会报
   「Parent node is busy setting up children」。
3. **GDScript 的 lambda 按值捕获局部变量**：测试里 `var captured := 0; func(): captured += 1`
   永远读到 0。计数器要放字典 / 数组（引用语义）。
4. **测试不能真的换场**：`change_scene_to_file` 会把测试场景自己 free 掉，断言就没地方写。
   所以留了 `SceneRouter.suppress_scene_change`（只改状态不换场景），**只在测试里置 true**；
   真实换场由截图脚本端到端跑（牧场→屋内→牧场→镇上→商店→矿洞，全部 `current_scene` 路径核对过）。
5. **房间不能比视口小**：房间 512×352 而视口 640×360，相机 limit 比视口小 → 屏幕四周露黑边。
   改成 640×360 正好一屏。
6. **`Vector2` 没有 `.end`**（那是 `Rect2` 的成员）—— `PANEL_POS.end.y` 是解析错误。
7. **房间场景要自己转接 `dialogue_requested`**：`DialogueUI` 只是显示层，订阅在主场景。
8. **`pool` 里多个存档位要防「手动覆盖自动档」**：面板 S 对槽 0 直接 no-op（自动档只由跨日写）。
9. **`meta` 必须现算**：房间场景里时间照样在走，如果照抄离开牧场那一刻的 meta，
   在屋里存出来的档会写着「第 9 天」，实际已经是第 12 天。
