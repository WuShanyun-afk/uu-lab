## 2. 建筑数据结构

### 2.1 `BuildingDef`（CSV 一行的强类型壳）

> 需求写的是「Resource」。项目里选择 **RefCounted + CSV** 而不是 `.tres` Resource：
> ① 数值平衡要能直接给策划改（CSV 比 .tres 好改，也不会把二进制 UID 搞丢）；
> ② 和已有的 `AnimalData` / `CropData` / `HousingDB` 保持同一套写法；
> ③ Resource 的真正好处是「编辑器里拖资源引用」，而这些数据全是运行期查表，用不上。
> 如果以后要做「建造配方编辑器」，再给 `BuildingDef` 加 `extends Resource` 也不冲突。

  id, display_name, category, size(Vector2i)

  capacity_housing, capacity_base, capacity_step     ← 棚舍容量
  efficiency, stage_required, note
  build_days                                        ← 模块 12 新增工期

### 2.2 住宅为什么不在 buildings.csv

住宅是「玩家自己的房子」：有独立室内场景、三级功能解锁、家具摆放。
硬塞进 buildings 表会让那张表长出一堆只有住宅用得上的列。所以：

```
data/house_levels.csv
level,name,wood,stone,gold,unlock,interior
1,小木屋,0,0,0,睡觉·存档·摆家具,一张床和一只旧木箱
2,木屋带厨房,40,8,2500,做饭（每日1次·出家常菜）,多了灶台和锅
3,带地下室的房子,80,20,6000,酿酒（每日1次·出蜂蜜酒）,地板上有地窖门
```

真源等级 = `GameState.house_level`（进存档）。升级工期写在 `HouseDB.BUILD_DAYS`：Lv2 要 2 天、Lv3 要 3 天。

## 3. 建造流程（需求 2）

```
商店买「建造许可证」（permit · 600G） + 木材 / 石头 / 金币
        ↓
B 进建造模式 → J/K 选建筑 → 幽灵预览（绿=可放 / 红=原因）
        ↓  E 确认
main._try_place():
   can_place 判定（含「正在施工」占位）
   → 判许可证 → 判钱 → 判木 → 判石
   → 扣款扣料扣证
   → build_days == 0 ? 当场落成 : Construction.start()（进施工队列）
        ↓ 每个跨日
main._tick_construction(): days_left -1 → 0 → _build_now()（真正落地 + 节点生成）
        ↓
施工期间：BuildSiteNode 画虚线框 + 「施工中 1/2 天」；该 footprint 不可再放东西
```

**为什么施工要单独一个队列而不是「先落建筑 + 盖块布」**：
建筑一落地就给加成（床位 / 加工速度 / 背包格）。先落地再盖布 = 玩家可以「先盖后等」，
工期变成纯装饰。所以施工中的建筑**不存在于 BuildingGrid 里**，只存在于 `Construction` 队列，
`can_place` 检查 `sites.blocks(cell)` 保证不叠放。

## 4. 房屋升级（需求 3）

```
屋内对着「工作台」按 E
  → HouseDB.upgrade_cost(level) 判钱/木/石
  → 扣料 + GameState.house_upgrade_target / house_upgrade_days
  → 每次跨日 DayCycle 推进 1 天
  → 归零 → GameState.set_house_level(target) + 提示「解锁：做饭 / 酿酒」
  → 室内道具立刻重建（RoomScene._rebuild_house_props）
```

| 等级 | 外观/道具 | 新功能 |
|---|---|---|
| 1 小木屋 | 床 + 存档柜 + 工作台 | 睡觉（推进次日+自动存档）、存档、摆家具 |
| 2 木屋带厨房 | +灶台 | 做饭：牛奶×1+鸡蛋×1 → 家常菜（可卖 320G）；当天动物友好度 +5（次日结算生效） |
| 3 带地下室 | +地窖门 | 酿酒：蜂蜜×2 → 蜂蜜酒（可卖 380G） |

做饭的 buff 实现：`GameState.buffs[&"warm_meal"] = 当天`，回牧场补结算时
`consume_buff(&"warm_meal", 那一天)` → 全牧群 `gain_affection(5)`。用「消费型 buff」而不是
「当日全局倍率」，因为跨场景时牧场不在场，倍率会漏算。

## 5. 室内外场景切换（需求 4）

沿用模块 11 的 `SceneRouter`，这里补的是「屋内随等级变化」：

```
牧场 ──E 小屋门──▶ SceneRouter.travel("house","door")
                        │ change_scene_to_file(res://scenes/house.tscn)
                        ▼
                 RoomScene(room_id=house)
                   ├─ _build_house_props()：按 GameState.house_level 生成道具
                   │    Lv1 床/存档柜/工作台
                   │    Lv2 +灶台   Lv3 +地窖门
                   ├─ _draw_furniture()：画玩家摆的家具
                   └─ F 摆/收家具（真源 GameState.furniture，进存档）
                        │
        E 床 ────────────┘ sleep：DayCycle.sleep_to_next_day() + 自动存档(SLOT_AUTO)
        E 门 ─────────────▶ travel("farm","house_door") → main 接 carry
                                            │
                                            └─ _catch_up_days()：在屋里睡掉的天数，
                                               牧场补跑 _on_day（作物/牧群/工期/订单）
```

**关键点：睡觉必须能跨场景生效**。睡觉推进的是 `GameClock.day`，但牧场不在场景树里，
`_on_day` 没人跑。所以回牧场时用「存档里的天数 vs 当前天数」的差值补结算（上限 7 天）。
这样「在屋里睡 3 天再出门」和「在牧场跨 3 天」结果一致。

## 6. 家具摆放（需求 4 · 可选）

- 家具是普通物品（`rug` 地毯 / `plant` 盆栽，杂货铺有卖）。
- 屋内按 **F**：脚下有家具 → 收回背包；否则把背包里的家具放到脚下格。
- 真源 `GameState.furniture = [{id,x,y}]`，进存档；`RoomScene._draw` 每帧画。
- 网格吸附用 `WorldConfig.px_to_cell`（32px），和建造系统同一套坐标。

## 7. 时间联动（需求 5）

- **睡觉才推进到次日**：`GameClock.sleep_next_day()` 单独一个入口，和 2:00 的强制入睡分开。
- **超过 2:00 不睡 → 强制昏倒**：`GameClock._roll_day` 发 `EventBus.forced_sleep`，
  `DayCycle` 收下 → 扣 `COLLAPSE_FEE = 120G`（钱不够扣到 0）→ `minutes = 120`（起得晚）。
  做成 autoload 的原因：玩家在屋内时 main 不在场，但昏倒罚金必须照扣。

## 8. 踩过的坑

1. **施工中的建筑不能进 BuildingGrid**：否则加成提前生效、存档里多一栋「其实没盖完」的建筑。
2. **许可证要排在「钱不够」前面判**：玩家会误以为只是缺钱。
3. **`_build_now` 失败必须退钱退料退证**：`can_place` 和 `place` 是两次判定，改代码时容易不同步。
4. **回场补结算要有上限**（7 天）：手改存档 / 时钟跳变时不会一次结算出一年的作物。
5. **`GameState.new()` 不行**：GameState 是 autoload（一个 Node 实例），`.new()` 会去调 `Node.new()`。
   测试里要验 roundtrip，用 `to_dict()` → 改值 → `from_dict()` 再断言。
6. **住宅不在 buildings.csv**：它有独立室内场景和三级功能，硬塞会把表结构撑歪（见 §2.2）。
7. **`F` 键要判 `ui_modal`**：存档面板 / 对话开着时不能顺手摆家具。
8. **房间道具位置要按 640×360 排**：模块 11 的房间已改成整屏，道具坐标对不上会跑到墙里。
9. **老测试要跟着改**：模块 9 的 `_try_place` 现在要许可证 + 石头 + 工期（测试里加 `_flush_sites` 快进）；
   模块 11 的床从「弹对话」变成「睡觉推进次日」。这类跨模块行为变更必须写进测试注释。
